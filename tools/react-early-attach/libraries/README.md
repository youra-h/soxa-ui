# Сравнение Tabs: Ark UI, Radix UI, shadcn/ui

Проверка по запросу владельца 16.11.2026: воспроизводится ли проблема дочерних
Tabs и Suspense/fallback в других React-библиотеках. Исходники Soxa не меняются.

## Запуск

Из корня репозитория:

```sh
node tools/react-early-attach/libraries/compare.mjs
```

Команда создаёт временный npm-проект, ставит закреплённые пакеты без install
scripts, получает два официальных исходника shadcn и выполняет SSR/jsdom опыты
в отдельных процессах. Путь временного проекта печатается. Для повторного
использования этой установки задать `TABS_COMPARE_DIR` её точным путём.
В существующей папке принимается только private fixture с ожидаемым именем.
Корневые package.json, lock и node_modules репозитория не изменяются.

На повторной чистой установке применяется сохранённый полный lock через npm ci.
Исходники shadcn сверяются SHA256 с сохранёнными registry JSON; обновление
поставщика требует отдельного обновления снимка. MIT-лицензия сохранена рядом.

После compare.mjs выполнить:

```sh
node tools/react-early-attach/libraries/browser.mjs <временный-проект>
node tools/react-early-attach/libraries/audit.mjs <временный-проект>
```

Browser runner использует Vite и Playwright текущего репозитория, поднимает
временный localhost сервер, запускает headless Chromium и закрывает их в конце.
CSS shadcn не подключается: проверяются HTML, поведение и состояния, не дизайн.

## Условия

React/React DOM 19.3.1; Ark UI 5.40.0; Radix Tabs 1.2.1; shadcn new-york-v4
из официального registry на radix-ui 1.8.1; shadcn base-nova на Base UI 1.9.0.
Фактические версии, транзитивные зависимости и хеши исходников — в results.

44 серверных случая: для каждой реализации активна первая/вторая вкладка,
обычный SSR, приостановка с fallback, разрешившийся поток, настоящий abort
потока, поздний собственный panel id; отдельно отсутствие defaultValue.
16 jsdom случаев: синхронная гидратация, разрешение Suspense, удаление
приостановленной ветки без её повтора, StrictMode и переключение.
Четыре browser-последовательности: гидратация с проверкой исходных узлов,
клик, ArrowRight во время fallback и после удаления ветки, позднее появление B.

Матрица использует штатный consumer API. Вкладка B лежит перед приостанавливающим
Wait внутри одной границы; A и C, владелец и панели находятся снаружи. В потоковом
случае fallback сам является Trigger с value="fallback". Передача active в Trigger
не имитируется: такого контракта выбора у этих библиотек нет.

| Число tab-кнопок с tabindex=0 до JS                          | 1    | 0     | 0              | 0             |
| В завершённом потоке нет кнопки fallback                     | Да   | Да    | Да             | Да            |
| Chromium: ArrowRight обходит отсутствующую B и фокусирует C  | Да   | Да    | Да             | Да            |
| Chromium: после удаления ветки ArrowRight снова фокусирует C | Да   | Да    | Да             | Да            |
| Chromium: после разрешения B появляется и выбирается кликом  | Да   | Да    | Да             | Да            |
| Синхронная Chromium-гидратация сохраняет узлы                | Да   | Да    | Да             | Да            |
| Console/recoverable diagnostics в browser-сценариях          | 0    | 0     | 0              | 0             |

При выбранной родителем B и недоступной кнопке B панель B всё равно выводится:
её выбор не зависит от успешного монтирования кнопки. При таком разбиении
Suspense aria-labelledby панели временно указывает на отсутствующую кнопку.
Это наблюдаемое ограничение композиции, не доказательство фантомной регистрации.

При передаче произвольного собственного id только панели Ark/Radix также
сохраняют формульный aria-controls, который с этим id не совпадает. Ark имеет
отдельный root ids-контракт; опыт его намеренно не использует, поскольку
проверяется поздний id на дочерней панели. Base UI готовит парные ссылки после
клиентской регистрации: в проверенном SSR активной панели нет aria-labelledby,
у активного Trigger нет aria-controls; после гидратации они появляются.

Ноль SSR Tab-остановок у Radix/Base не приравнивается к выполнению требования Soxa
об одной остановке до JS. У Radix после гидратации входом в группу становится
tablist; непосредственно кнопка получает остановку после фокуса. Это отдельный
компромисс, а не свидетельство полного совпадения accessibility-контрактов.

## Почему исходная ошибка Soxa не воспроизвелась

Их активность задаётся на владельце:

```tsx
<Tabs.Root defaultValue="b">
  <Tabs.List>
    <Tabs.Trigger value="a">A</Tabs.Trigger>
    <Tabs.Trigger value="b">B</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Content value="b">PANEL-b</Tabs.Content>
</Tabs.Root>
```

Root знает выбранное value до выполнения дочерних компонентов. Trigger и Content
сравнивают собственное value с родительским. Поэтому Content не ждёт регистрации
Trigger в коллекции, чтобы решить, активен ли он.

Проверка установленных исходников подтверждает это: Radix ведёт root value через
useControllableState и передаёт Context; сбор элементов для обхода регистрируется
эффектом с cleanup. Ark читает root value из state machine, вычисляет selected
сравнением value и для обхода запрашивает реальные DOM-элементы. Base ведёт root
value через useControlled и регистрирует панели в layout-effect. shadcn добавляет
обёртки/оформление к соответствующим примитивам. Точные исходные файлы, строки и
SHA256 сохранены в [source-audit.json](./results/source-audit.json).

Это архитектурное отличие, а не доказательство наличия у них улучшенного TDrafts.

## Границы вывода

[comparison.json](./results/comparison.json) содержит полный HTML и jsdom-снимки;
[browser.json](./results/browser.json) — результаты настоящего Chromium.
Ошибки кандидатов и диагностика сохраняются данными. Выполнение runner само по
себе не означает прохождение всех критериев: нужно читать состояния и ошибки.

В проверенных сценариях не обнаружены выбор фантомной вкладки и её попадание в
реальный клавиатурный обход. Это **не доказательство отсутствия утечек памяти**:
heap/WeakRef-аудит внутренних машин, registries и подписок этих библиотек не
проводился. Нельзя переносить результат на все компоненты, версии, Next/RSC или
SSR-адаптеры иных фреймворков.
