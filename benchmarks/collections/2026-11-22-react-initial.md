# React initial после коммита, 22.11.2026

В Chromium подготовленные коллекции из 1000 элементов удерживают на 0,79 MiB
меньше для Tabs и на 0,50 MiB для Tags. После коммита адаптер освобождает
квитанции транзакций и ключи черновиков. При подписке React переключает
`TStableSnapshot` с временного ARIA-порта на состояние обмена. Если содержимое
совпало, React получает прежний снимок. Подготовленный источник переиспользует
уже сгенерированные идентификаторы табов и панелей. [Задача 1an4hvw6vdk](https://app.clickup.com/t/1an4hvw6vdk).

## Клиентская память, MiB

Куча после GC со смонтированной коллекцией сверх пустой страницы. Медиана
трёх прогонов на одном Windows 11 Pro, Node 24.20.0, React 19.3.1 и Chromium
156.0.8078.4. Порядок версий обращён во втором прогоне. Каждый прогон содержит
семь циклов измерений на клетку по протоколу `client-v3-isolated-phases`.
Версии, порядок и сырые измерения — в [manifest.json](raw/2026-11-22-react-initial/manifest.json).

| Коллекция | `items`, до → после | `initial`, до → после | Надбавка `initial`, до → после | Изменение `initial` |
| --------- | ------------------- | --------------------- | ------------------------------ | ------------------- |
| Tabs      | 31,34 → 31,21       | 32,42 → 31,63         | +1,08 → +0,41                  | −0,79               |
| Tags      | 21,00 → 20,89       | 21,78 → 21,28         | +0,78 → +0,39                  | −0,50               |

Подготовленные коллекции по-прежнему удерживают больше памяти, чем `items`.
Принятый `TPluginMount` хранится в bundle и плагинах без очереди эффектов и
заплаток. Подготовленный источник остаётся доступен при повторной сборке.

## Время монтирования, мс

Каждое значение — медиана семи измерений до готовности DOM. Разница между
версиями на пути `initial` меняет знак от прогона к прогону. Для Tabs
медиана трёх значений снизилась со 108,4 до 102,4 мс, для Tags — с 70,2 до
66,8 мс. Разброс не позволяет подтвердить устойчивое ускорение.

| Коллекция | Путь      | До, по прогонам       | После, по прогонам    |
| --------- | --------- | --------------------- | --------------------- |
| Tabs      | `items`   | 87,5 / 91,0 / 85,2    | 82,0 / 93,3 / 86,7    |
| Tabs      | `initial` | 113,9 / 108,4 / 108,0 | 100,5 / 115,1 / 102,4 |
| Tags      | `items`   | 60,0 / 59,5 / 59,2    | 56,8 / 55,3 / 55,3    |
| Tags      | `initial` | 75,2 / 70,2 / 66,6    | 65,3 / 66,8 / 84,3    |

Все 24 клетки прошли проверки количества элементов, выбранного элемента,
одной Tab-остановки и взаимных ARIA-ссылок для Tabs.

## Снимки кучи

Отдельные production-сборки с `build.minify = false`. После трёх циклов
прогрева коллекцию снова монтировали и снимали кучу через CDP
`HeapProfiler.takeHeapSnapshot` после паузы 1200 мс и GC.

| Объекты                  | Tabs `initial`, до → после | Tags `initial`, до → после |
| ------------------------ | -------------------------- | -------------------------- |
| `TCollectionTransaction` | 2001 → 0                   | 1001 → 0                   |
| `TCollectionAriaState`   | 4000 → 0                   | 2000 → 0                   |

После коммита квитанции удерживал `TBuilt._receipt`. Порты ARIA оставались
в `TStableSnapshot._state` и в замыканиях подписок. Реестр транзакций живёт
на движке, а коммит убирает из него запись. Сторож в React проверяет
достижимость обоих типов объектов при живой коллекции.

## Воспроизведение

Возьмите полные хеши из [manifest.json](raw/2026-11-22-react-initial/manifest.json).
Подготовка зависимостей и темы описана в [README](README.md).

```powershell
node tools/bench-collections/prepare.mjs --prepare --revisions=baseline=<base>,optimized=<head>
node tools/bench-collections/build.mjs --fw=react --client-only --variant=baseline,optimized
node tools/bench-collections/run.mjs --n=1000 --run=my-run --variant=baseline,optimized --fw=react --libs=soxa --surface=client --modes=data,initial
node tools/bench-collections/compare.mjs my-run baseline optimized
```
