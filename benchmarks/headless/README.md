## Протокол supported-recipes-v2

Используются опубликованные пакеты Soxa React 0.4.2, Ark React 5.40.0 и Radix 1.8.1;
React/ReactDOM 19.3.1. Точные версии и tarball integrity всех зависимостей закреплены
в [отдельном lock-файле](../../tools/bench-headless/package-lock.json). Alias на исходники
монорепозитория отсутствуют. Source-файлы и сборка находятся в [стенде](../../tools/bench-headless/).

Сравнивается полный поддерживаемый рецепт каждого участника. Для SSR Soxa используется
предназначенный для этого initial; Root/List/Trigger/Content и параметры Ark/Radix сохраняются.
Функции библиотеки не отключаются ради размера или заранее ожидаемого непрохождения.
Soxa без initial в матрицу этого протокола не входит.

Все три участника без CSS-тем, наборов иконок и сбросов страницы. У Soxa не подключаются Oren,
theme-base/setup и useTheme. Текстовые индикаторы задаются публичными слотами. Функциональные
стили самих библиотек сохраняются. Отсутствие отдельного CSS-файла не означает отсутствия
inline-style или runtime-стилей.

| Сценарий              | Soxa                              | Ark                                      | Radix                                             |
| --------------------- | --------------------------------- | ---------------------------------------- | ------------------------------------------------- |
| Форма Name + Accept   | Input, CheckBox, Label            | Field, Checkbox                          | native input, Checkbox, Label                     |
| Tabs Alpha/Beta       | Tabs initial, две панели          | Tabs Root/List/Trigger/Content           | Tabs Root/List/Trigger/Content                    |
| Dialog Settings       | Dialog visible, событие изменения | Dialog Root и полный состав частей       | Dialog Root, Portal и полный состав частей        |
| Выбор Alpha/Beta      | Select items                      | Select + ListCollection                  | Select и полный состав частей                     |
| Ввод Bet и фильтрация | Select editableMode=filter        | Combobox + коллекция и фильтр приложения | отдельного эквивалента в проверенном каталоге нет |
| Прикладная страница   | форма + Tabs + Dialog + Select    | тот же набор сценариев                   | тот же набор сценариев                            |

Количество частей и внутренние дефолты библиотек могут различаться: сравнивается задача
пользователя, а не число DOM-узлов. У Radix текстовое поле нативное — отдельного общего Input
в Primitives для этого рецепта нет. Combobox Radix не заменяется сторонним стеком и не получает
нулевой размер. В примерах Ark overlay размещён внутри дерева, Radix использует Portal,
Soxa выполняет собственный Teleport; clipping/stacking и дизайн overlay отдельно не тестируются.

## Воспроизведение

```powershell
cd tools/bench-headless
npm ci --no-audit --no-fund
npx playwright install chromium
npm run typecheck
npm run bench
```

Каждый запуск создаёт новую папку с UTC-временем. Новую папку можно указать через
`npm run bench -- --out <path>`. Существующий run.json не перезаписывается.
`node registry.mjs` сохраняет отдельный новый снимок npm metadata для закреплённых версий.

1. Для каждой точки входа выполняются три production-сборки esbuild: minify, tree shaking,
   ES2022, NODE_ENV=production, automatic JSX. Несовпадение размеров повторов останавливает прогон.
2. Полный JS включает React/ReactDOM, пример и hydrateRoot с общей диагностической проводкой.
   Baseline — тот же runtime и параграф. Baseline не вычитается из gzip/Brotli: сжатие нелинейно.
   Каждый выходной файл сжимается отдельно: gzip 9, Brotli 11. JS/CSS записываются отдельно.
3. `attribution` содержит только модули с положительным esbuild bytesInOutput. Это raw-вклад
   кода в выходную сборку, не независимый gzip-размер пакета. `inputs` включает и просмотренные
   сборщиком модули; их наличие само по себе не доказывает попадание в итоговый JS. Для каждого
   примера сохраняется SHA-256 JS-сборки.
4. renderToString создаёт сохраняемый дословно HTML. Chromium сначала открывает его без JS,
   затем в отдельном контексте выполняется hydrateRoot. Сохраняются выбранность, панели,
   IDREF, tabindex, диагностические сообщения и наблюдение за сохранностью исходных элементов.
5. Общий SSR-критерий Tabs: выбран Alpha, активная панель есть, активная пара ID взаимна.
   Серверное число tab stops и ссылки неактивных панелей сохраняются как отдельные наблюдения.
   Они не смешиваются с ошибками гидратации. После гидратации проверяются настоящий вход Tab
   и ArrowRight. В совместной странице вход Tab начинается с предыдущего checkbox.
6. Проверяются имена полей, ввод, Space и FormData, Select, фильтрация Combobox, Dialog с
   асинхронным переносом фокуса, Escape и возвратом фокуса. Общая страница проходит те же действия
   вместе. Диагностика сервера или браузера делает соответствующую проверку неуспешной.

Все проверки записываются в checks; summary содержит полный список непрохождений.
Код 0 означает завершение сбора данных, а не автоматическое прохождение всех проверок.
Ошибки сборки или запуска браузера останавливают прогон. Изменение всех DOM-узлов после
инициализации не трактуется автоматически как ошибка гидратации: компонент может законно
добавлять и удалять вспомогательные элементы после mount.

## Область выводов

Замер ограничен React renderToString/hydrateRoot и Chromium. Streaming, RSC, Suspense с
отложенными данными, другие адаптеры, WebKit/Firefox, screen readers, контраст и полный WCAG
не проверялись. Времени монтирования, задержки ввода, памяти и утечек в этом эксперименте нет.
Количество JSX-частей или строк примера не выдаётся за скорость разработки.

При смене версии библиотеки или инструмента создаётся новый прогон. Исторические HTML/JSON
сохраняются, а новый отчёт ссылается на свой протокол и набор примеров. Исходный протокол v1
ошибочно включал пример без initial в общую оценку SSR; его итоги заменены supported-recipes-v2.
Историческая запись в журнале и raw-файлы оставлены для прослеживаемости и не являются
действующим результатом сравнения.
