## Условия сравнения

Основное сравнение выполняется на React, потому что Radix Primitives — библиотека React.
Поддержка остальных фреймворков описывается по публичным контрактам, а не экстраполируется
из React-замеров. Используются опубликованные npm-пакеты, без alias на исходники монорепозитория.
Точные прямые и транзитивные версии зафиксированы отдельным lock-файлом стенда.

Ark UI и Radix Primitives не требуют готовой визуальной темы. Поэтому Soxa измеряется без
Oren, без theme-base/setup и без useTheme. Никто не подключает CSS-тему, Tailwind, сброс
страницы или набор иконок. В примерах используются текстовые индикаторы; у Soxa — через
публичные слоты. Это исключает предупреждения о незарегистрированных иконках. Runtime-стили,
которые выставляет сам компонент, сохраняются: это часть его поведения и JS-стоимости.
Нулевой CSS в таблице означает отсутствие отдельного CSS-файла сборки, а не отсутствие
inline-стилей или CSS, который библиотека может создать в браузере.

Сравниваются задачи пользователя, а не одинаковое число частей:

| Сценарий                    | Soxa                                 | Ark UI                              | Radix Primitives                         |
| --------------------------- | ------------------------------------ | ----------------------------------- | ---------------------------------------- |
| Простая форма               | Input, CheckBox, Label               | Field, Checkbox                     | нативный input, Checkbox, Label          |
| Tabs: две вкладки           | Tabs с initial, две панели           | Tabs                                | Tabs                                     |
| Дополнительный SSR-контроль | обычные Tabs.Item active без initial | —                                   | —                                        |
| Dialog                      | Dialog, controlled visible           | Dialog                              | Dialog                                   |
| Select: два варианта        | Select                               | Select и ListCollection             | Select                                   |
| Combobox с фильтрацией      | Select editableMode="filter"         | Combobox и фильтр данных приложения | нет отдельного эквивалента в этой версии |

Форма содержит Name и Accept. Вкладки — Alpha/Beta и их панели. Dialog открывается кнопкой
Open, содержит Settings, текст, поле Name и Close; проверяются Escape и возврат фокуса.
Select/Combobox выбирает Beta; combobox дополнительно скрывает Alpha при вводе Bet.
Компоненты сохраняют обычные внутренние возможности: библиотечные дефолты не вырезаются
ради одинакового DOM. Это сравнение минимальных прикладных рецептов, а не изолированных
внутренних движков. У Radix обычное текстовое поле нативное, поскольку отдельного общего
Input в Primitives здесь нет.

## Как повторить

```powershell
cd tools/bench-headless
npm ci --no-audit --no-fund
npx playwright install chromium
npm run typecheck
npm run bench
```

Стенд: [tools/bench-headless](../../tools/bench-headless/). По умолчанию каждый прогон создаёт
новую папку с UTC-временем в results. Для заданной новой папки: `npm run bench -- --out <path>`.
Не перезаписывайте опубликованный датированный прогон. Запускайте из чистого checkout с
указанным lock-файлом; версии npm/Node могут влиять на установку и сжатие.

1. Для каждой точки входа esbuild делает три независимые production-сборки: minify,
   tree shaking, ES2022, NODE_ENV=production, автоматический JSX runtime.
2. JS включает React, ReactDOM, код библиотеки и пример с hydrateRoot. Baseline содержит
   тот же React/ReactDOM и простой параграф. В таблице полные байты, baseline не вычитается.
   Одна точка входа не импортирует примеры других сценариев после tree shaking.
3. Каждый выходной файл сжимается отдельно: gzip level 9, Brotli quality 11. Все три результата
   сохраняются; несовпадение размеров между сборками останавливает прогон. JS и CSS разделены.
   Импорт Oren или Material Icons, как и выходной CSS-файл, останавливает этот headless-прогон.
4. renderToString даёт HTML, сохранённый без переформатирования. Chromium открывает страницу
   без JS для снимка до гидратации, затем в отдельном контексте — с hydrateRoot. Сохраняются
   ID-ссылки, выбранность, tabindex и панели, состояние после гидратации, диагностические сообщения
   и сохранность серверных элементов.
5. Сценарии проверяются ролями и доступными именами. Асинхронный фокус ожидается по DOM-состоянию.
   Сравнение отдельно проверяет вход Tab и ArrowRight: программный focus не заменяет проверку Tab.

Непройденная проверка компонента записывается в JSON с ошибкой; это результат сравнения,
а не повод остановить независимые сценарии. Код возврата 0 означает завершённый сбор данных,
а не отсутствие продуктовых находок. Ошибка сборки, запуска браузера или недетерминированный
размер останавливает прогон. Для оценки результата читайте checks и diagnostics в JSON.

## Границы

Это не тест пропускной способности, LCP, памяти, утечек или мобильной скорости. Такие числа
здесь не измеряются. Время сборки не выдаётся за runtime performance. Результаты сборки
относятся к данным точкам входа и esbuild, а не гарантируют тот же размер в Next.js/Vite.
SSR ограничен React renderToString/hydrateRoot: streaming, RSC-границы, Suspense с отложенными
данными и остальные адаптеры этим прогоном не проверены. Проверка IDREF показывает
неразрешённые ссылки, но сама по себе не является полным заключением по ARIA.

Проверки браузера покрывают указанные действия, имена и фокус. Не выполнены ручные прогоны
NVDA/VoiceOver, весь WCAG, axe-аудит, WebKit/Firefox, мобильные устройства, forced colors,
визуальное оформление и все состояния компонентов. Отсутствие предупреждений не заменяет эти
проверки. Прохождение сценария Dialog не доказывает работу focus trap во всех случаях.

## Обновление

При обновлении любой библиотеки/React/сборщика: отдельный lock, новая папка результатов,
повтор всех сопоставимых примеров и новая датированная запись в react.md. Старые записи и
HTML не переписываются. Проверяйте официальный API и ссылки заново; registry.json — снимок
версий на дату исследования, а не обещание будущей latest-версии. Отсутствующий эквивалент
не получает нулевой размер. Перед переносом утверждения на сайт сохраняйте рядом дату,
версии, сценарий, отсутствие темы и ссылку на соответствующий прогон.
