# Soxa UI, Ark UI и Radix Primitives: что получает разработчик

**22 ноября 2026.** Сравнение опубликованных Soxa React **0.4.2**, Ark React **5.40.0**
и Radix Primitives (`radix-ui`) **1.8.1** на React/ReactDOM **19.3.1**.
Все примеры работают **без CSS-тем и пакетов иконок**.

Soxa предлагает готовые композиции компонентов, общий слой моделей и коллекций и шесть
адаптеров: React, Vue, Angular, Solid, Svelte и Web Components. Разработчик может задавать
поведение через props и события компонента или управлять им через публичную модель `ctrl`.
Практический смысл такого устройства — использовать один набор понятий для состояния,
коллекций и компонентов в разных интерфейсах, сохраняя отделённое от фреймворка ядро.
[Архитектура Soxa](../../docs/architecture.md), [публичные поверхности управления](../../docs/agents/setup.md).

В проверенных рецептах Soxa берёт на себя состав Select и его фильтрацию, а для SSR Tabs
предоставляет сериализуемую декларацию `initial`. Все поддерживаемые примеры Soxa прошли
проверки серверного HTML, гидратации и взаимодействий. Ark и Radix также прошли свои
сопоставимые сценарии. Измеренная область для улучшения Soxa — объём JS; отдельная задача
поставлена на уточнение ARIA-ссылки неактивной панели Tabs.

## Что Soxa берёт на себя в приложении

### Select и фильтрация

В Soxa структура поля, списка и опций создаётся компонентом из `items`. Для редактируемого
выбора включается `editable`; для фильтрации — `editableMode="filter"`. В проверенном примере
приложение не хранит отдельный `query` и не фильтрует массив вручную:

```tsx
<Label text="Choice">
  <Select
    editable
    editableMode="filter"
    items={items}
    arrow-icon={<span aria-hidden="true">Choose</span>}
    item-indicator-icon={<span aria-hidden="true">Selected</span>}
  />
</Label>
```

В сопоставимом Ark-примере приложение задаёт `Combobox.Root`, Label, Control, Input,
Trigger, Positioner, Content и Item, а также коллекцию и реакцию на ввод. Это даёт явное
управление деревом частей. Soxa предоставляет эту композицию внутри Select и оставляет
приложению данные, режим и слоты. Сравнивается рабочий рецепт; количество строк не
используется как измерение трудозатрат или доказательство возможностей всего API Ark.

[Рабочий пример Soxa](../../tools/bench-headless/src/soxa.tsx),
[рабочий пример Ark](../../tools/bench-headless/src/ark.tsx),
[официальный Ark Combobox](https://ark-ui.com/docs/components/combobox).
Radix Select даёт выбор и typeahead; его не подменяли текстовым Combobox:
[Radix Select](https://www.radix-ui.com/primitives/docs/components/select).

### Модели и коллекции

У Soxa компонент связан с моделью из независимого core, а дескрипторы и плагины подключают
поведение к адаптеру. Поэтому публичная поверхность включает не только разметку, но и `ctrl`,
события и механизмы коллекций. Для проектов, где состояние и действия должны управляться
прикладной логикой за пределами шаблона, это конкретная архитектурная возможность.
[Две поверхности управления](../../docs/agents/setup.md), [механизм коллекций](../../docs/agents/collections.md).

У Ark также есть общий слой поведения на Zag.js и инструменты коллекций. Отличие следует
оценивать по нужным контрактам конкретного проекта: форма событий, модель данных, работа
с внешним состоянием и состав компонента. Переход между библиотеками требует адаптации
этих контрактов; одинаковые названия Tabs или Select не делают их взаимозаменяемыми.
[Архитектура Ark](https://ark-ui.com/docs/overview/about),
[Ark List Collection](https://ark-ui.com/docs/collections/list-collection).

### Оформление

В данном сравнении ни одна библиотека не подключает готовую тему: у Soxa нет Oren,
`theme-base/setup` и `useTheme`, у конкурентов нет дополнительных систем оформления.
Сохраняются функциональные inline-стили и runtime-поведение самих компонентов.
У Soxa вместо набора иконок используются публичные слоты с текстовыми индикаторами.

Для пользователя Soxa доступны оба варианта — собственное оформление headless-компонентов
или отдельная готовая Oren. Стоимость Oren в приведённые числа не включена. Ark и Radix
также предполагают оформление приложения; например, геометрию Dialog Overlay у Radix
задаёт потребитель. Наши проверки покрывают управление, фокус и Escape, а не дизайн overlay.
[Ark Styling](https://ark-ui.com/docs/guides/styling),
[Radix Styling](https://www.radix-ui.com/primitives/docs/guides/styling).

## SSR: проверка работающих рецептов

Soxa использует предназначенный для SSR вход `initial`: состав элементов и панелей известен
до сериализации HTML. Например, приложение объявляет `items`, `panels` и активность первой
вкладки; части панели связываются с декларацией через `initial={0}` и `initial={1}`.
Этот же состав передаётся на первый клиентский рендер.
[Полный рецепт Soxa](../../docs/ssr-collections.md),
[проверенный пример](../../tools/bench-headless/src/soxa.tsx).

Ark и Radix используют полный состав своих Root/List/Trigger/Content и `defaultValue="alpha"`.
Ни у одного участника из примера не удаляются необходимые части или параметры.
[Ark Tabs](https://ark-ui.com/docs/components/tabs),
[Radix Tabs](https://www.radix-ui.com/primitives/docs/components/tabs).

| Проверка Tabs                                  | Soxa с initial | Ark      | Radix    |
| ---------------------------------------------- | -------------- | -------- | -------- |
| Выбранный Alpha указан в серверном HTML        | да             | да       | да       |
| Активная панель присутствует до выполнения JS  | да             | да       | да       |
| ID активного таба и панели взаимно связаны     | да             | да       | да       |
| Гидратация без ошибок и предупреждений         | да             | да       | да       |
| Вход Tab и переход ArrowRight после гидратации | проходят       | проходят | проходят |

Отдельный снимок до JS показывает одну явную точку `tabindex="0"` на табах у Soxa и Ark;
у Radix оба таба имеют `tabindex="-1"`. Это различие серверной разметки сохранено в данных.
После гидратации проверенный вход Tab работает у всех трёх. Оно не превращено в общий
вывод об отсутствии SSR у Radix.

У Soxa неактивная панель ещё не смонтирована, но её таб уже имеет `aria-controls` с будущим ID.
Активная пара при этом корректна. Проверка допустимости этой ссылки и её влияния на
доступность выделена в [отдельную задачу](https://app.clickup.com/t/1an4hvw70vr).
Это отдельная деталь жизненного цикла ARIA-связи, а не регрессия работающего SSR через initial.

Проверялся React `renderToString` с последующим `hydrateRoot`. Streaming, Next.js RSC и
остальные адаптеры данным прогоном не измеряются.

## Проверенное поведение и интеграция

Новый прогон включает **18 точек входа и 64 проверки; все 64 проходят**, диагностических
сообщений сервера и браузера нет. Проверены доступные имена полей, ввод, Space для Checkbox,
серверное состояние Tabs, гидратация, Tab/ArrowRight, открытие Dialog, попадание фокуса внутрь,
Escape, возврат фокуса, выбор Beta и фильтрация Bet. Общая страница проходит совместный сценарий.
Это проверка конкретных пользовательских действий. Ручные прогоны NVDA/VoiceOver, контраст,
все состояния focus trap и полный аудит доступности остаются за границами этого исследования.

Контракты внешнего состояния различаются. Например, controlled-диалог Soxa использует
`visible` и `onChangeVisible` с `newValue`; Ark — `open` и `onOpenChange` с полем `open`;
Radix — `open` и `onOpenChange` с boolean. В наших рабочих рецептах Soxa показывает управление
из приложения, Ark и Radix — внутреннее состояние Root. Они проходят одно пользовательское
действие открытия/закрытия; это не тест всех возможных controlled/uncontrolled конфигураций.
[Примеры всех трёх библиотек](../../tools/bench-headless/src/),
[Ark Dialog API](https://ark-ui.com/docs/components/dialog),
[Radix Dialog API](https://www.radix-ui.com/primitives/docs/components/dialog).

Переход потребует заменить композицию частей, события и структуру данных, адаптировать CSS
и повторить проверку формы, фокуса и SSR. Интеграции с моделями и Collection Engine потребуют
отдельной адаптации. Количество часов миграции без конкретного приложения здесь не оценивается.
Все три проекта открыты под MIT; сведения о лицензиях и версиях сохранены в
[манифестах npm](results/registry.json). Поддержка Ark связана с командой Chakra UI, Radix —
с WorkOS; сведений о гарантированном SLA эти факты не дают.

## Вывод

**Soxa — выбор для проекта, которому нужны готовые композиции компонентов, управление через
модели и единая архитектура для шести фреймворков.** Select с фильтрацией и SSR Tabs в этом
сравнении показывают, как приложение задаёт данные и поведение через публичный контракт,
а библиотека выполняет связанную работу. При необходимости к этому подходу добавляется
готовая Oren, сохраняя возможность собственного оформления.

**Ark — близкая альтернатива для headless-интерфейсов на четырёх поддерживаемых фреймворках**
с Zag.js, коллекциями и явной композицией частей. **Radix — выбор для React-дизайн-системы**,
когда нужны составные примитивы и важна небольшая JS-сборка в проверенных сценариях.

Следующий шаг для Soxa — сохранить эти возможности и снизить стоимость их доставки,
а также проверить деталь ARIA-связи ленивой панели. Обе задачи имеют воспроизведение и
критерии приёмки. Улучшение будет оцениваться повтором тех же рабочих сценариев.
