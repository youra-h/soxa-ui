# Soxa UI против Ark UI и Radix Primitives

Дата исследования: **22 ноября 2026**. Soxa React **0.4.2**, Ark React **5.40.0**,
Radix `radix-ui` **1.8.1**. Это сравнение опубликованных пакетов; сайт с документацией
Soxa 0.3.0 не становится документацией 0.4.2 автоматически.

## Что выбрать

**Soxa стоит рассматривать**, когда нужны общий слой моделей и коллекций, адаптеры для
React, Vue, Angular, Solid, Svelte и Web Components, а также возможность использовать
готовую Oren отдельно от компонентов. Цена этого выбора в измеренных React-примерах —
более крупная JS-сборка и собственные контракты моделей, событий и SSR-подготовки.

**Ark UI стоит рассматривать**, когда нужен набор headless-компонентов для React, Vue,
Solid и Svelte, в том числе отдельный Combobox и инструменты коллекций, с архитектурой
на Zag.js. Это наиболее близкая альтернатива Soxa по идее общего поведения между
фреймворками. Angular и Web Components отсутствуют в официальном списке адаптеров Ark;
это не утверждение о невозможности самостоятельной обёртки.
[Архитектура и фреймворки Ark](https://ark-ui.com/docs/overview/about).

**Radix Primitives стоит рассматривать**, когда приложение на React и нужны составные
примитивы для собственного дизайн-системного слоя. В наших общих примерах Radix даёт
самые небольшие JS-сборки. Отдельного Combobox в проверенном каталоге Primitives нет;
Select нельзя считать эквивалентом редактируемого поля с фильтрацией. Radix Themes —
другой продукт и в сравнении не участвует.
[Введение и каталог Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction).

## Сценарии и отсутствующие эквиваленты

Простую форму, Tabs, Dialog и Select можно собрать на всех трёх библиотеках. У Soxa
часть структуры и действий уже внутри компонента; у Ark/Radix разработчик явно размещает
больше частей. Это сокращает разметку потребителя Soxa, но требует принять её структуру,
слоты и систему моделей. Больше частей у конкурента означает больше работы над обёрткой,
одновременно предоставляя прямой контроль над композиционным деревом.

У Soxa для редактируемого выбора используется `Select editable`, для фильтрации списка
в примере нужен `editableMode="filter"`. У Ark это отдельный Combobox с коллекцией;
фильтрация данных в нашем примере находится в приложении. У Radix Select есть выбор
и typeahead, но это не текстовый combobox с фильтром. Дополнять Radix сторонней библиотекой
в такой строке означало бы сравнивать другой стек, поэтому его ячейка отсутствует.
[Ark Combobox](https://ark-ui.com/docs/components/combobox),
[Radix Select](https://www.radix-ui.com/primitives/docs/components/select).

Soxa также имеет Table/Virtual и общее API моделей коллекций. У Ark есть иные специализированные
сценарии, например File Upload, Signature Pad, Tour. Наличие Accordion/Select/Tabs у двух
библиотек не означает эквивалентности всего набора. В этом исследовании не реализованы
большая таблица, виртуализация, дерево или все варианты меню: выводов об их скорости нет.
Списки доступного API проверяются по [Soxa exports](../../packages/ui/react/src/index.ts)
и официальным каталогам [Ark](https://ark-ui.com/docs/overview/about),
[Radix](https://www.radix-ui.com/primitives/docs/overview/introduction).

## Оформление: равные условия

Ark и Radix Primitives предоставляют headless-поведение, оформление задаёт приложение.
В нашем сравнении **все три библиотеки без CSS-темы**, включая Soxa. Oren, theme-base/setup,
Material Icons, Tailwind и сторонние сбросы не подключены. Обычные встроенные runtime-стили
сохраняются. Нулевой CSS-файл не означает, что библиотека никогда не пишет inline-style.
[Ark Styling](https://ark-ui.com/docs/guides/styling),
[Radix Styling](https://www.radix-ui.com/primitives/docs/guides/styling).

Практическая стоимость собственной дизайн-системы включает разметку, функциональные стили,
цвета, состояния, токены и проверку доступности. Например, Radix прямо возлагает на приложение
стили покрытия viewport для Dialog Overlay. У Soxa готовая Oren — отдельный вариант поставки,
который здесь не измерялся. Смешивать её CSS и поведение с headless-замерами конкурентов нельзя.
[Функциональные стили Radix](https://www.radix-ui.com/primitives/docs/guides/styling).

Текстовые индикаторы передаются через публичные слоты Soxa, поэтому пакет иконок не нужен
и предупреждений о незарегистрированных иконках в итоговом прогоне нет. При создании своей
темы надо оформить части компонента и скрытие вспомогательных элементов; эти примеры не
являются готовым визуальным дизайном.

| Форма               |           95.00 / 82.23 |          81.88 / 70.95 |            73.45 / 63.39 |
| Tabs (Soxa initial) |          104.35 / 90.23 |          81.90 / 70.99 |            76.88 / 66.33 |
| Dialog              |           98.03 / 84.84 |          90.13 / 78.28 |            81.20 / 70.20 |
| Select              |         125.28 / 107.79 |         101.10 / 87.54 |            99.30 / 86.15 |
| Combobox с фильтром |         125.30 / 107.84 |         102.09 / 88.51 |                        — |

Baseline без библиотеки: 67.59 / 58.12 KiB (gzip / Brotli). KiB = 1024 байта.

Полные байты самостоятельной страницы с React/ReactDOM, примером и hydrateRoot.
Это не размер одного npm-пакета и не добавочная стоимость компонента в существующем приложении.
Baseline нельзя механически вычитать из gzip/Brotli и объявлять разность размером библиотеки:
сжатие совместного кода нелинейно. Примеры имеют одинаковую задачу, но разную внутреннюю
структуру и набор дефолтных возможностей. По трём сборкам каждого примера размеры совпали.
CSS-файлы всех точек входа: 0 байт. Полные raw/gzip/Brotli и три повтора — в журнале.

**В этом наборе примеров Soxa не выигрывает по размеру JS.** Это сохраняется и без темы.
Упрощённая разметка потребителя не означает меньшую сборку. По этим числам нельзя делать
вывод о задержке ввода, потреблении памяти или скорости монтирования: они здесь не измерены.
[Методика](README.md), [React-журнал](react.md), [исходные результаты](results/2026-11-22-final/run.json).

## SSR и гидратация

| Вариант Tabs             | Выбран Alpha на сервере | Точек Tab у табов на сервере | Активная панель в SSR | Вход Tab / ArrowRight после гидратации |
| ------------------------ | ----------------------- | ---------------------------: | --------------------- | -------------------------------------- |
| Soxa initial             | да                      |                            1 | да                    | проходят                               |
| Soxa обычный declarative | нет aria-selected       |           0 явных tabindex=0 | нет                   | проходят                               |
| Ark                      | да                      |                            1 | да                    | проходят                               |
| Radix                    | да                      |          0 (оба tabindex=-1) | да                    | проходят                               |

У обычных декларативных табов Soxa отсутствие tabindex не означает, что нативная кнопка физически недоступна Tab: это отсутствие заданной точки roving focus и начального ARIA-состояния коллекции. Вариант с initial решает выбранность и активную панель. У Soxa initial до и после гидратации ссылка aria-controls неактивного таба указывает на ещё не смонтированную панель; у Ark/Radix в этом состоянии неразрешённых IDREF в снимке нет. Это отдельное наблюдение, не скрытое успешной проверкой активной пары.

Все 16 примеров прошли гидратацию без предупреждений консоли и recoverable hydration errors. Признак сохранности всех исходных DOM-элементов false у Radix Select: он отражает также обычные удаления элементов при клиентской инициализации, поэтому не используется как доказательство ошибки гидратации или полной замены корня.

SSR-поддержка и корректный HTML конкретного составного сценария — разные проверки.
Заявление Radix о SSR совместимо с тем, что отдельные детали фокуса требуют клиентского
состояния; ограничения React до 18 к нашему React 19.3.1 не относятся.
[Radix SSR](https://www.radix-ui.com/primitives/docs/guides/server-side-rendering).

У Soxa `initial` — сериализуемое объявление состава на первое монтирование, не механизм
поиска произвольных ещё не отрендеренных детей. Для активного таба и связей панелей серверу
нужен состав заранее. Используется одно и то же объявление на сервере и первом клиентском
рендере; дальнейшее управление выполняется обычным API коллекции.
[Публичный рецепт SSR Soxa](../../docs/ssr-collections.md).

Все выводы ограничены renderToString/hydrateRoot этих React-примеров. Streaming SSR,
Next.js App Router/RSC, нестандартные обёртки и задержанные Suspense-поддеревья здесь не
проверялись. Работоспособность остальных адаптеров требует собственных прогонов.

## Доступность

В завершённом прогоне: **16 примеров, 44 проверки, 2 непрохождения**, оба относятся к указанному SSR-критерию Tabs (Soxa без initial и Radix без серверной точки Tab). Все остальные проверки проходят; диагностических сообщений браузера: **0**. Это результаты именно перечисленных рецептов и критериев, не рейтинг доступности библиотек целиком.

Проверены доступные имена полей, ввод текста, Space для CheckBox, вход Tab/ArrowRight для
Tabs, выбор опции, фильтрация, фокус внутри открытого Dialog, Escape и возврат к Open.
Имена и роли проверены в браузере, а не только по обещаниям документации. Прохождение
этого набора не означает WCAG-сертификацию или завершённый аудит. Ручные screen reader
прогоны, полный focus trap, контраст и остальные ограничения перечислены в методике.

## Поддержка и риск внедрения

Все три проверенных пакета лицензированы MIT. Soxa — проект со своим слоем моделей и
адаптеров; Ark поддерживается командой за Chakra UI; Radix Primitives развивается как
проект WorkOS. Это факты об устройстве проектов, а не гарантия SLA или скорости исправлений.
[Ark Team](https://ark-ui.com/docs/overview/about),
[Radix Introduction](https://www.radix-ui.com/primitives/docs/overview/introduction),
[лицензии пакетов](results/registry.json).

Звёзды GitHub, число пользователей в production, «enterprise readiness» и скорость ответа
maintainer не измерены. Оценок зрелости по номеру major нет. Для выбора важнее проверить
свои критичные компоненты, совместимость версии фреймворка, нужные расширения и готовность
поддерживать собственные прикладные обёртки.

## Цена миграции

Например, одно controlled-состояние диалога приходится переподключать так:

```tsx
// Soxa
<Dialog visible={open} onChangeVisible={({ newValue }) => setOpen(newValue)} title="Settings">
  {children}
</Dialog>

// Ark
<Dialog.Root open={open} onOpenChange={({ open }) => setOpen(open)}>
  {/* Trigger, Backdrop, Positioner, Content, Title, Description, CloseTrigger */}
</Dialog.Root>

// Radix
<Dialog.Root open={open} onOpenChange={setOpen}>
  {/* Trigger, Portal, Overlay, Content, Title, Description, Close */}
</Dialog.Root>
```

Это схема адаптации события, не самостоятельный полный пример; рабочие варианты с частями
и содержимым проверены типами и браузером:
[Soxa](../../tools/bench-headless/src/soxa.tsx),
[Ark](../../tools/bench-headless/src/ark.tsx),
[Radix](../../tools/bench-headless/src/radix.tsx).

Для миграции надо заменить импорты и дерево частей, преобразовать payload событий,
адаптировать структуру данных (`text`/`label`, значения и коллекции), заново написать стили
для DOM/классов/data-атрибутов целевой библиотеки, проверить привязку Label и нативную форму,
внешнее управление состоянием и SSR. Для Tabs в Soxa добавляется декларация `initial`,
если нужен заранее корректный состав на сервере. Код, который использует ctrl/Collection Engine,
потребует замены этих интеграций: одинаковые визуальные компоненты не дают drop-in API.
Оценка миграции в часах без конкретного приложения была бы выдумкой.

## Использование на сайте и в статьях

Можно публиковать проверенные сценарные выводы и таблицу вместе с датой, версиями,
React 19.3.1 и условием «без CSS-тем у всех участников». Нельзя превращать этот материал
в заявления «Soxa быстрее», «Radix не поддерживает SSR» или «все адаптеры одинаково доступны».
При смене версий нужен новый прогон. Исходные данные и примеры сохраняют проверяемость
статьи; прежние бенчмарки Soxa с Oren к этой таблице не относятся.
